## 3. Architecture

### 3.1 Principles
- UI never contains rules. UI calls services/controllers and listens to state.
- Pure Dart for rules (engine, generator, solver) so it can be unit-tested without Flutter.
- Heavy work (generation + solving) runs in an isolate (`compute`) and is cached.
- Everything is local. One `SaveData` object saved as JSON in `shared_preferences` (v1).

### 3.2 Packages to add
`flutter_riverpod` (state), `google_mobile_ads` (AdMob + UMP), `firebase_core`, `firebase_analytics`,
`firebase_crashlytics`, `audioplayers` (sound/music), `in_app_review`, `url_launcher`, `package_info_plus`.
Already present: `shared_preferences`, `google_fonts` (replace by bundled Outfit font before release), `device_preview` (dev only).
Do NOT add `in_app_purchase` / billing.

### 3.3 Folder layout (add next to existing `lib/core`, `lib/widgets`, `lib/screens`)
```

  models.dart         Bottle, Board, Move, LevelSpec
  engine.dart         GameEngine: legal moves, pour, win check, undo stack
  difficulty.dart     DifficultyCurve: level -> LevelSpec params
  generator.dart      LevelGenerator: LevelSpec + seed -> Board
  solver.dart         Solver: solve(Board) -> moves, par, hint
```

## 4. Game design and rules

### 4.1 Board model
- A bottle is a stack (bottom to top) of color ids `0..11` with `capacity` K (4, 5 or 6).
- Level start: C colors, each color appears exactly K times, spread randomly; **C + 2 bottles** (the last 2 empty).
- Color ids map to `AppColors.liquid` (extend to 12 colors; keep 8 existing + 4 new distinct: teal, lime, brown, grey-blue).
- Bottle painter: layer height = 72 / K (today it is fixed 18 for K=4).

### 4.2 Move rules
- Move `from -> to` is legal if: from is not empty, to is not full, and (to is empty OR top color of to == top color of from).
- Pour moves the whole run of equal top colors from `from` that fits in the free space of `to`.
- A move that pours a whole bottle that is already uniform (full or not) into an empty bottle is allowed but counted as a move.
- Win: every bottle is empty or full with a single color (K units).
- Stuck (fail): no legal move exists and not won -> Level failed popup.
- Moves counter = number of successful pours. Undo reverses the last pour and **decreases** the counter? No: undo does not
  decrease the counter (prevents star abuse); it is increased by 1 for an undo as well. (Keep the rule simple: counter counts every pour and every undo.)

### 4.3 Helpers
- **Undo**: pops the history. 3 free per level; the 4th and later require a completed rewarded ad each.
- **Hint** (40 gems or rewarded ad): ask Solver for the best next move from the current board; highlight source and target
  for 2 s; hint does not move bottles. If the board is unsolvable from here (player painted into a corner) the hint says
  "Undo a few moves" and highlights the Undo button.
- **+Bottle** (70 gems or rewarded ad): adds one empty bottle (capacity K) once per level. Persisted in `inProgress`.

### 4.4 Difficulty curve (levels 1..500)
Colors C(n):
- n 1-10: 3 + floor((n-1)/4)  -> levels 1-4 = 3, 5-8 = 4, 9-10 = 5
- n 11-60: linear 5 -> 8 (round)
- n 61-200: linear 8 -> 11 (round)
- n 201-500: linear 11 -> 12 (round)
- Breather: every n % 10 == 0 (n > 10): C = max(3, C - 2).
Capacity K(n):
- 1-30: 4
- 31-100: 5 if n % 4 == 0 else 4
- 101-300: 4 if n % 3 == 0 else 5
- 301-500: 6 if n % 10 == 5 else 5
Bottles B = C + 2. Layout: B <= 8 -> 2 rows of 4; <= 10 -> 2x5; <= 12 -> 2x6; <= 14 -> 2x7; with +Bottle may use 3 rows. Bottle width shrinks to fit (min ~30 dp).
Level 1 = C 3, K 4, B 5. Background index = ((n - 1) ~/ 20) % 6.

### 4.5 Stars and par
- Solver returns a solution length `solverMoves` (best found, bounded search). `par = solverMoves`.
- Moves counter `m` (pours + undos).
- 3 stars: m <= ceil(par * 1.15) + 1; 2 stars: m <= ceil(par * 1.5) + 2; else 1 star.
- Reward gems: 10 / 15 / 20. Rewarded ad doubles the reward once.
- Level 1-3 (tutorial): always 3 stars.

### 4.6 Level generator (seeded, solvable)
Seed = `levelNo * 7919 + 13` (fixed forever so every device gets the same level). Daily challenge seed = `yyyyMMdd`.
Algorithm (like the common competitors):
1. Start from the solved state: C full bottles + 2 empty.
2. Apply random REVERSE moves for N steps (N = 60 + 12*C): choose a random source with a top unit, random destination with
   space, move 1..run units where the reverse of a legal pour is valid (destination top color may differ - this "unmixes" a solved board).
   Keep a rule: never create a state identical to a previous state in the last 10 steps.
3. Reject if already solved or if too easy (solver par < C + 2).
4. Verify with the Solver (time/node budget). If not solved in budget, retry with seed+1 (record attempt number in the level cache).
5. Cache {level -> board, par}. Generate next 2 levels in the background after the player starts a level.
Alternative if reverse moves give boring boards: random fill of K units per color then solver check (accept only if solvable).

### 4.7 Solver
- State = list of bottles, canonicalised by sorting bottles (so permutations match) and hashed.
- Search: best-first / A*: cost = moves, heuristic = sum over bottles of (number of color changes) + count of non-empty
  non-uniform bottles. Node cap 300k (isolate). Return the move list.
- Hint = first move of the solution from the CURRENT state (re-solve with a small budget; if budget fails fall back to a greedy
  legal move: prefer pouring onto the same color, avoid moving a uniform bottle, avoid ping-pong).
- Solver must be deterministic.

### 4.8 Daily Reward (no gameplay)
- One claim per local day. Day index 0..6 maps to 20,30,40,50,60,80,150 gems. After day 7 -> day 1.
- Missed a full day -> streak and day index reset to day 1.
- Rewarded ad after claiming gives the same amount again (x2) once per day.
- Native ad shown on the Daily Reward screen only (section 6.4).

### 4.9 Daily Challenge (gameplay)
- One puzzle per local date, seed = yyyyMMdd, C = 10, K = 5 (Hard), always solvable.
- Win -> +30 gems, challenge streak +1, date added to `doneDates` (calendar tick). Failing/leaving costs nothing; can retry the same day.
- Weekly bonus: when all 7 days Monday-Sunday of the current ISO week are in `doneDates` -> Claim button gives **40 gems** once per week.
- Past days cannot be played later.
- Clock guard (all daily features): keep `guard.lastSeenMs`. On every app start/resume, if `now < lastSeenMs - 5 min`
  the clock was rolled back: block daily claims and challenge completion until `now >= lastSeenMs`. Otherwise update lastSeen.

### 4.10 Economy (gems)
Income: level win 10/15/20, daily reward, challenge 30, weekly bonus 40, rewarded ad 10 (max 3 per day = 30), welcome gift 100 (once).
Spend: Hint 40, +Bottle 70, shapes 700/1500/3000/6000, backgrounds 200/200/300/400/400.
Sanity: ~15 gems per level and ~10 levels/day = 150/day + daily ~55 avg + ads 30 -> first shape (700) in about 4 days, last (6000) in a few weeks.
Rules: never allow negative gems; spending is atomic (check, subtract, save). Not enough -> Not enough gems popup with "watch ad +10" option (respecting the 3/day cap; if cap reached show "Come back tomorrow").

### 4.11 Shop
- **Free Gems** tab (replaces Gem packs): card "Watch ad, get 10 gems" with counter "2/3 today". No prices in money anywhere. Remove "Remove Ads".
- **Bottles**: Cone, Flask free; Test Tube 700, Potion 1500, Jar 3000, Diamond 6000. Equipped shape is saved and shown on Home and Game.
- **Backgrounds**: "Auto" chip (default) follows the level; levels unlock backgrounds automatically; locked ones can be bought with gems (200/200/300/400/400).
  Equipping a specific background pins it; tapping Auto returns to level-based.

### 4.12 Level map / stats
Level map reads `level` (current), `stars`. Stats screen reads totals from SaveData. Profile shows real nickname/avatar/level and stats.
Rate-us: use `in_app_review` after level 10 and level 30 (once each), never during gameplay.

### 4.13 Sound / haptics
CC0 sounds: tap, lift, pour loop, bottle full chime, win jingle, fail, button click, coin. Music: one calm loop (volume 0.4).
Settings switches persist. Haptics via `HapticFeedback` (light on tap, medium on full bottle, heavy on win).
Colorblind mode: draw a small symbol per color on each liquid layer (circle, square, triangle, star, plus, ...).

## 6. Ads architecture (AdMob + UMP)
### 6.1 Startup order
1. Launch -> Splash. 2. Consent screen (our Agree). 3. **UMP**: request consent info; show form if required (EEA/UK/CH);
only after `canRequestAds` is true call `MobileAds.instance.initialize()`. 4. Preload interstitial + rewarded.
No ad request before UMP. Add "Ad privacy options" in Settings (re-open UMP form when required).

### 6.2 Formats and rules
- **Interstitial**: after a level is completed (not on fail, not on pause), every 3rd completed level, at least 90 s since
  last interstitial, never in levels 1-3, never during the first session's first 5 minutes. Show after the Level complete popup
  closes by "Next". Never on app start.
- **Rewarded**: always opt-in and labelled ("Watch ad: +10 gems"). Placements: Shop free gems (3/day), 2x level reward,
  2x daily reward, free hint, free +Bottle, extra undo, Not-enough-gems popup. Grant reward only in `onUserEarnedReward`.
- **App Open**: only when returning to the app (resume), >=4 h since last app open ad, max 2 per day, never in first session,
  never before consent, never while a rewarded/interstitial just closed (ignore the resume caused by an ad).
- **Native**: only on the Daily Reward screen, below the claim area, clearly marked "Ad", never overlapping buttons.
- Policy details: no fake close buttons, no ad placed where taps are likely by accident, ads must not cover game controls.

### 6.3 Config
`ad_config.dart`: test unit IDs by default (debug); real IDs injected for release (`--dart-define` or a git-ignored file).
`tagForChildDirectedTreatment: false`, `tagForUnderAgeOfConsent: false`, `maxAdContentRating: T`.
Add `com.google.android.gms.permission.AD_ID` and the AdMob App ID meta-data to AndroidManifest.

### 6.4 Analytics events (Firebase, no personal data)
`level_start{level}`, `level_win{level,stars,moves}`, `level_fail{level}`, `hint_used`, `extra_bottle_used`, `undo_used`,
`ad_rewarded_shown{placement}`, `ad_interstitial_shown`, `daily_claimed{day}`, `challenge_done`, `shop_equip{item}`.
Never log nickname. Crashlytics enabled in release only.
